# Branch & Tag Hygiene

## Practice

Repositories accumulate stale refs over time: auto-generated IDE branches
(`cascade/...`), pre-push snapshot branches (`scratch/merge/...`), and
checkpoint tags (`tags/auto/...`). Without a structured archiving workflow,
these refs pollute `git branch` output, slow down `git fetch`, and make it
harder to identify active work.

### Archive Format

Archive stale branches and tags into a structured namespace:

```
archive/{branches,tags}/{type}/YYYY/MM/YYYYMMDD-{slug}[-pre|-post]
```

Where `{type}` is a conventional-commit type (`feat`, `fix`, `chore`, `doc`,
`refactor`, etc.) plus `auto` for IDE-generated refs and `scratch` for
transient snapshots. The date is derived from the ref's **last commit date**,
not the current date, so archives group by when the work happened.

### Ownership Exception

When the repository's upstream remote is **not** owned by the primary account
(e.g., `levonk/`), defer to the repo's own archiving conventions instead of
injecting `archive/` refs. Upstream projects have their own branch naming,
tagging, and release conventions that would be disrupted by foreign ref
patterns.

### Pruning

Archive refs older than a retention period (default 6 months) can be pruned
permanently. Pruning is destructive and requires explicit confirmation — always
run with `--dry-run` first.

### Squash-Merge Detection

Squash-merged branches (common in GitHub PR workflows) have no ancestry link
to the main branch — `git merge-base --is-ancestor` reports them as
"unmerged" even though their patch content is already in main. Without
squash-merge detection, these branches accumulate indefinitely because the
archiving script misclassifies them as active.

The fix is to use `git cherry <main> <branch>` in addition to
`merge-base --is-ancestor`. `git cherry` compares commits by patch content
(equivalence class), not ancestry. Output lines starting with `-` mean the
commit's patch is already in main; lines starting with `+` mean it is not. If
all lines are `-` (or output is empty), the branch is fully squash-merged and
safe to archive.

This pattern was borrowed from `arc90/git-sweep` (inspector.py), which uses
`git cherry upstream head` to detect squash-merged branches for cleanup.

## Failure Mode

Without archiving:

- `git branch` output grows to dozens or hundreds of refs, making it hard to
  find the branch you actually need.
- `git fetch` downloads refs for branches that were merged months ago.
- IDE branch pickers become unusable (Cascade/Windsurf generated 42 branches in
  one repo over a month).
- Checkpoint tags (`tags/auto/...`) accumulate at 2+ per git-repository-management
  run, producing hundreds of tags over time.
- New contributors can't tell which branches are active vs abandoned.

## Prevention

1. **Run `git-archive.sh --identify` periodically** (monthly or after major
   merges) to find archive candidates.
2. **Archive immediately after merging** a feature/chore branch — don't wait
   for the next cleanup cycle.
3. **Auto-generated branches** (`cascade/...`) are always safe to archive —
   they have no human author intent and are regenerated by the IDE as needed.
4. **Pre-push snapshots** (`scratch/merge/...`) are safe to archive once the
   push completes and the branch is on the remote.
5. **Checkpoint tags** (`tags/auto/...`) are safe to archive once the commit
   they point to is in the main branch's history.
6. **Never archive protected branches** (`env/dev`, `main`, `master`, `develop`,
   `dev`, `staging`) — the script enforces this automatically.

## Source

- Real-world accumulation in `levonk/dotfiles`: 75 local branches (42 cascade,
  27 scratch, 6 other) and 29 tags (22 auto-checkpoint, 5 feature/task, 2
  legacy archive) accumulated over 2 months without a structured archiving
  workflow.
- The `git-repository-management` skill v1.10.0 introduced the `git-archive.sh`
  script and the `archive/{branches,tags}/{type}/YYYY/MM/YYYYMMDD-{slug}` format.
- The `arc90/git-sweep` project (Python, MIT licensed) demonstrated the
  `git cherry` squash-merge detection pattern and the fetch-before-scan,
  `--skip`, and confirmation-prompt UX patterns. These were incorporated into
  `git-archive.sh` in v1.11.0.
